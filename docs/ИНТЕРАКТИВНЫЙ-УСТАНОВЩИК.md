# Интерактивная установка на RemnaNode 3.4.3

Установщик предназначен для **уже работающей** RemnaNode 3.4.3 под Linux. Он не создаёт панель, DNS, Host, сертификаты или Config Profile. Для первичной установки ноды используйте [официальную инструкцию Remnawave](https://docs.rw/install/remnawave-node/), затем вернитесь сюда. Не запускайте установщик одновременно с обновлением ноды или профиля.

## Что понадобится

- Root на сервере ноды, Python 3, Git и Docker с плагином Compose.
- Нода с образом `remnawave/node:3.4.3` или `ghcr.io/remnawave/node:3.4.3`, работающая в отдельном Compose-проекте (обычно `/opt/remnanode`).
- Свободное место и память для Rust-сборки; сборка выполняется в контейнере с лимитом 3 ГиБ.
- Отдельный тестовый профиль в панели для проверки выбранного протокола. Для VLESS/REALITY задавайте `fingerprint=firefox`.

## Запуск меню

```sh
git clone https://github.com/vpnsaintp/RAST-xray-for-remnanode.git
cd RAST-xray-for-remnanode
sudo python3 install.py
```

Откроется меню:

```text
RAST · RemnaNode 3.4.3
1. Состояние ноды и ядра
2. Собрать Rust-ядро из исходников
3. Установить уже собранный бинарник
4. Протоколы и варианты подключения
5. Вернуть штатное ядро
0. Выход
```

Сначала выберите **1**. Установщик покажет образ, контейнер, текущую версию ядра и цель ссылки `rw-core`. Затем выберите **2** для сборки. Команда закрепляет версию `reality-rs`, применяет находящийся в репозитории патч и выполняет `cargo build --locked --release` в Docker. Бинарник будет в `prototype/target/release/nightvpn-xray-rust-prototype`.

Выберите **3** и вставьте абсолютный путь к этому бинарнику. Установщик проверит Linux ELF, архитектуру и команду `version`, затем покажет SHA-256 и попросит ввести `УСТАНОВИТЬ`. До этого ввода он не меняет Compose. После подтверждения он создаёт отдельный `compose.rast.yaml`, дописывает управляемую строку `COMPOSE_FILE` в `.env`, пересоздаёт только `remnanode` и проверяет новую версию через `/usr/local/bin/rw-core version`. Секреты `.env` не печатаются и не попадают в Git.

Установщик откажется менять ноду, если версия образа не 3.4.3, контейнер не работает, уже используется `xray-custom`, в `.env` или окружении задан свой `COMPOSE_FILE`, либо есть файл `compose.rast.yaml`. Для нестандартного Compose-проекта используйте ручной способ и проверьте итоговую конфигурацию самостоятельно.

## Как выбрать протокол

Пункт **4** показывает поддерживаемые варианты и для выбранного пункта подсказывает настройки отдельного тестового Config Profile. Меню **не переписывает** профиль панели и не раздаёт новый протокол всем клиентам. После сохранения профиля проверьте Host, подписку, соединение, выходной IP, учёт трафика, отзыв пользователя и мониторинг. [Матрица протоколов](ПРОТОКОЛЫ.md) и [чеклист проверок](ПРОВЕРКИ.md) объясняют ограничения.

## Откат

Выберите **5** и введите `ОТКАТ`. Скрипт удалит только созданную им Compose-вставку, пересоздаст сервис и подтвердит, что `rw-core` снова указывает на штатный `/usr/local/bin/xray`. Установленный бинарник остаётся на диске для анализа; это не влияет на работающую ноду. Если `.env` изменён после установки, автоматический откат остановится, чтобы не потерять новые настройки. Тогда воспользуйтесь [ручным возвратом](УСТАНОВКА-REMNANODE-3.4.3.md#5-возврат).

Для нестандартного каталога:

```sh
sudo python3 install.py --project-dir /путь/к/compose
```

Для проверки без меню: `python3 install.py status`; для возврата: `sudo python3 install.py rollback`. Скрипт не меняет SSH, брандмауэр, IPv6, DNS и маршрутизацию сервера. Эти действия выполняются отдельно по вашей схеме после проверки доступности.
