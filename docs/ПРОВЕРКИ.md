# Проверки перед выдачей клиентам

1. Собрать с `--locked`, выполнить `cargo test --locked --release` и `prototype/test_remnawave.py` в изолированной среде. Нужны Docker, Python 3, OpenSSL и официальный Xray-бинарник версии, указанной в README.
2. Отдельно испытать каждый включаемый транспорт: успешный HTTPS и UDP, отказ неверного UUID/пароля, отзыв активного пользователя, добавление нового пользователя без ручного рестарта.
3. Сверить для одного клиента: реальные входной и выходной IPv4, Remnawave traffic delta, online IP, события торрент-монитора. На ноде с двумя IPv4 исходящий трафик обязан идти только со второго IPv4.
4. На мосте проверить сценарии без PROXY и с доверенным PROXY; недоверенный источник должен быть отклонён. Автоматическая блокировка не должна блокировать IP моста.
5. Проверить Happ, Incy и Mihomo на реальных клиентах с `firefox`, обновлением подписки, пингом и открытием сайтов. Тесты с другим fingerprint не заменяют эти проверки.
6. Сравнить со штатным Xray при одинаковой нагрузке: CPU на гигабайт, пик RSS, p50/p95/p99 подключения, пропускную способность, ошибки и восстановление после рестарта. Испытать минимум прямую ноду и мост с несколькими одновременными пользователями.
7. До публикации: секрет-сканирование, сохранение MPL-2.0 и лицензий `reality-rs`, CI на фиксированном коммите, готовый откат. Не помещать в Git ключи, токены, UUID клиентов, ссылки подписок, дампы БД и реальные конфигурации панели.

Пока эти условия не выполнены для конкретного протокола, его наличие в исходниках не означает готовность к общему продакшену.
